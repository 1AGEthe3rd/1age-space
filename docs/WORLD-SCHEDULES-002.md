Base: validated World Scheduling 001 PR #34, commit 5aa4225e232a473f0e849b0b22bc3ca7f2184722, validation run 45937816843. Stacked development only. HQ1 and HQ2 scenes, architecture, existing rail/flight gameplay and live main remain untouched.

## Shared integration
- Server-side, allowlisted station arrival service using TriMet Arrivals v2 and WMATA station predictions. Provider credentials come from TRIMET_APP_ID and WMATA_API_KEY environment variables; no credential or provider response is logged or returned to browser. Node 22 service has no dependencies. Requests are deduplicated and throttled per allowlisted station, with 30-second cache reuse, bounded upstream timeout, explicit unavailable state and CORS allowlist (WORLD_ALLOWED_ORIGINS). Production hosting must also enforce public traffic limits and provider quotas.
- Initial Portland station records: N Killingsworth (11503/11512), Interstate/Rose Quarter (11507/11508), Rose Quarter TC Red Line (8340/8377), PDX (10579). Filter to the associated MAX route; no invented arrival times. Source: https://trimet.org/max/stations.htm and https://developer.trimet.org/ws_docs/arrivals2_ws.shtml.
- Washington candidates: Anacostia F06, Navy Yard F05, DCA C10. Crosswalk is not verified against the authenticated official station catalog yet, so WMATA network calls fail closed. Prediction parser handles minutes and ARR/BRD as display-only states. See https://developer.wmata.com/ and https://www.wmata.com/about/developers.html.
- Shared canvas-texture station board displays official estimated versus scheduled arrivals and unavailable states. Board is an unmounted component: cities must supply a mesh, position, service endpoint, refresh cadence and disposal. Real-world arrival times are informational, not exact departure times, reservations or synchronized virtual trains.
